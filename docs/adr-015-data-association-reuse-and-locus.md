# ADR-015: Ассоциация данных — матрица self-attention, переиспользование точек и упрощённый локус

Дата: 2026-06-27  
Статус: **Предложено**

Связано: [ADR-007](./adr-007-trajectory-graph-kalman-worker.md), [ADR-009](./adr-009-osint-pre-collapse.md), [SDD phase-1c attention-assign](./sdd/tracking/phase-1c-attention-assign.md)

---

## Контекст

Текущая ассоциация (`assignCandidates.ts`) — **жадный per-candidate GNN**: точка обрабатывается одна за другой в хронологии, берёт `argmin linkCost`, после линковки **исключается** (`consumed.add(eventLocationId)`) и в следующий трек уже не попадёт. «Авто-расширение локуса» сейчас сделано через `pauseFactor`, который **раздувает ковариацию** (Q/мягкий gate) на паузах.

Рисёрч сравнил это с вероятностными схемами:

| Подход | Суть | Применимость к нам |
|--------|------|--------------------|
| **GNN (текущий)** | argmin, точка → 1 трек, consume | работает, но теряет неоднозначность |
| **PDAF** | взвешенная сумма in-gate точек на трек, update Σβᵢ | требует P_D/λ, даёт smearing |
| **JPDAF** | совместные гипотезы, точка ≤ 1 трек | дорого, конфликты гейтов у нас редки |

**Выводы рисёрча:**

- Поток разрежённый и уже дедуплицирован ST-DBSCAN ([ADR-009](./adr-009-osint-pre-collapse.md)) → в гейте трека обычно **одна** точка, поэтому вероятностное взвешивание (PDAF/JPDAF) даёт **низкий ROI** и риск «размазывания» (smearing) + неоткалибруемые `P_D`, `λ`.
- Реальная потребность OSINT — **сохранять неоднозначность**: одно сообщение («БПЛА над городом N») может легитимно питать **несколько** правдоподобных треков, а не разрешаться в один (JPDAF делает наоборот: точка ≤ 1 трек).
- «Авто-расширение локуса» через раздувание ковариации непрозрачно и плохо предсказуемо.

---

## Решение

### 1. Флаг переиспользования точек — `reuseAcrossTracks` (матрица self-attention)

Матрица `точка × трек` становится явной: для точки `i` строка — это все треки, в гейт которых она попадает по Махаланобису. Меняется **только шаг consume**, формула линковки лаконична:

```text
linksᵢ = { j : D_M²(i, j) ≤ χ²_gate }          // строка self-attention для точки i

reuse = off (дефолт, = текущее):
    assignᵢ = argmin_{j ∈ linksᵢ} linkCost
    consume(i)                                  // точка исключается из следующего шага

reuse = on:
    assignᵢ = linksᵢ                            // точка идёт во ВСЕ сходящиеся треки
    нет consume(i)                              // точка остаётся доступной
```

- **off** — поведение без изменений: точка, попавшая в трек, исключается из расчёта на следующем шаге.
- **on** — точка добавляется во все треки, где есть сходимость по Махаланобису (`inLocus`); fan-out гипотез сохраняется.

Это **не** PDAF/JPDAF: нет взвешивания `βᵢ`, нет смешанного update. Каждый трек получает точку как обычное наблюдение; неоднозначность выражается копией точки в нескольких треках, а не дробной вероятностью.

### 2. Локус = маневренная погрешность, без раздувания ковариации

Убираем динамический пересчёт ковариации (`pauseFactor`-инфляция) как механизм расширения локуса. Вместо этого — **чистый коэффициент попадания против фиксированного допуска маневра**:

```text
predict(track j, dt) → ẑ_j                      // прогноз позиции (Kalman predict)
ρ(i, j) = D_M²(i, j) / χ²_gate                  // чистый коэф попадания (без правки P)
допустимо ⟺ ρ(i, j) ≤ 1                          // в пределах заданной погрешности маневра
трек j берёт min_i ρ(i, j)                       // «лучшую точку с учётом греха» ρ
```

- Ковариацию **не меняем** на каждом шаге взвешиванием — `χ²_gate` фиксирован профилем (маневренный допуск).
- `ρ` — прозрачный «грех» (нормированный остаток): трек забирает лучшую (минимальный `ρ`) точку среди допустимых.
- Допустимость маневра = прогноз ± погрешность из `maxVelocityMs`/профиля за `dt`; covariance-inflation больше не требуется.

### 3. Связь с PDAF/JPDAF

Сознательно **не внедряем** вероятностное взвешивание сейчас. Модель неоднозначности — это `reuseAcrossTracks` (fan-out копий), а не `βᵢ`. PDAF/JPDAF остаются в backlog на случай, если замеры покажут много пересечений гейтов (высокий `attentionConflicts`).

### Конфиг и UI

- `trackingPipelineConfigSchema`: `reuseAcrossTracks: boolean` (default `false`).
- Админка (`TrackingKinematicsSettingsWidget`): галочка «Переиспользовать точки в нескольких треках» с пояснением (off — точка уходит в один лучший трек; on — во все сходящиеся по Махаланобису).
- Проброс: `shared` (`ResolveOpts`/`BuildMatrixOpts`) → `worker` (`assignBatch` → `resolveAssignments`).

---

## Не делаем

- Вероятностный update (PDAF/JPDAF), `βᵢ`-смешивание, оценку `P_D`/`λ` — backlog.
- Раздувание ковариации как механизм расширения локуса (`pauseFactor` для gate выводится из употребления).
- Дедупликацию копий точки между треками при `reuse=on` — неоднозначность намеренно сохраняется.
- Изменение схлопывания ([ADR-009](./adr-009-osint-pre-collapse.md)) и хранения треков ([ADR-007](./adr-007-trajectory-graph-kalman-worker.md)).

## Последствия

| Плюс | Минус |
|------|-------|
| Сохранение неоднозначности OSINT (один сигнал → N треков) | При `reuse=on` рост числа нод и возможное дублирование сегментов |
| Прозрачный локус (`ρ` против допуска) вместо непрозрачной инфляции P | `reuse=on` требует ревизии метрик покрытия (точка считается многократно) |
| Дёшево: без `P_D`/`λ` и enumeration гипотез | Не разрешает cross-track конфликты (это и не цель) |
| Флаг — обратимо, дефолт сохраняет текущее поведение | Два режима ассоциации в коде |

---

## Критерии принятия

- `reuse=off` даёт побитово текущее поведение (consume-once, argmin).
- `reuse=on`: точка с `D_M² ≤ χ²_gate` к двум трекам попадает в оба; unit-fixture это покрывает.
- Локус: при фиксированном `χ²_gate` решение зависит только от `ρ = D_M²/χ²_gate`, без модификации `P` между шагами.
- Галочка в админке управляет `reuseAcrossTracks`, значение доезжает до `resolveAssignments` (проверка через rebuild).
